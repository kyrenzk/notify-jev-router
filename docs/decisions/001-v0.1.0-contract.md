# ADR 001: v0.1.0 routing contract

## Status

Accepted (2026-09)

## Context

Issue #1 defines the MVP scope for notify-jev-router: typed routing via Jev with hard policy, partial/full fallback, and no PII in state.

## Decision

- **Output invariant**: successful `Resolve` always returns `len(Destinations) >= 1`; no skip / empty plan in v0.1.0.
- **Categories**: `security`, `billing`, `transactional` only; marketing is out of scope.
- **Policy over Jev**: `PolicyEngine` seeds required destinations; merge never clears `Required`.
- **Jev failure**: return a plan with `Metadata.FallbackMode = "full"` and `error == nil`.
- **Identifiers**: optional `subject_ref` only; `user_id` and contact fields are rejected at validate.
- **SDK**: `github.com/havlan/jev-go` behind `JevClient`; production model must be pinned (not `jev-latest`).

## Consequences

- Hosts always get a deliverable plan or a validation error before Jev is called.
- Shadow helpers and OSS packaging are tracked in Issue #3 (roadmap phases 2–3).
